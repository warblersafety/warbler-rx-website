# Editable mock EHR voice demo

The website now uses one fictional record editor and two conversation channels: browser audio and a requested telephone callback. Both send the same server-validated record as the `mock_ehr` dynamic variable. The provider prompt treats record content as untrusted fictional data and retains all existing clinical boundaries. Only the end-call tool is enabled.

The browser receives a signed session for an immutable agent version. Telephone calls use ElevenLabs' existing Twilio integration and the dedicated agent branch. No inbound phone routing is changed. The build script `scripts/publish-mock-ehr-agent.mjs`, enabled by `VOICE_EHR_PUBLISH=true`, reads the existing pinned website agent and publishes/reconciles a separate branch. It verifies privacy, authentication, tools, analysis and limits before writing nonsecret resource IDs to `lib/mock-ehr-agent.js`. Provider secrets remain server-side. A callback number is included only after a successful same-workspace readback identifying a Twilio integration.

Callbacks require explicit consent to one AI call to a number the visitor controls. Supported destinations are US/Canadian-format numbers, excluding known other NANP territories, premium and toll-free prefixes. Existing atomic database limits remain ten starts across the website and three per visitor/network in 24 hours. An additional hashed-recipient reservation allows only one callback to a number in 24 hours. Failed or uncertain requests are not refunded or automatically retried. Optional Twilio Verify can be enabled with the three TWILIO_* variables; partial configuration fails closed. Verification proofs are bound to the visitor and recipient and consumed atomically once.

No EHR fields or raw telephone numbers are stored in the quota database or application logs. ElevenLabs processes the edited record and voice; recording storage remains disabled and transcript retention remains at most one day. Twilio connects requested calls. Quota records contain hashes and timestamps; usage expires after 24 hours, but inactive hashed scope rows may remain until cleanup.

Local verification covers bounded input/context propagation, provider-config preservation, origin/consent checks, phone restrictions, optional proof replay, atomic admission order, duplicate-submit protection, provider failure handling and browser/phone mutual exclusion. Dedicated database integration tests require VOICE_LIMIT_TEST_DATABASE_URL. Browser layout checked at desktop and mobile widths. No real telephone calls or text messages are sent by tests.
